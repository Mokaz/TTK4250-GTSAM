\section*{Some background on the template code}
The template code is a trimmed-down version of a factor graph SLAM system built on \href{https://gtsam.org}{GTSAM}, the library referred to in Sec.\ 9.5 of the book. GTSAM provides the back-end: it holds the factor graph, maintains the Bayes tree, and solves for the MAP estimate incrementally with iSAM2. Everything that GTSAM does \emph{not} do -- building the right factors, recovering a covariance from the graph, and data association -- is either yours to implement or given in the front-end.

Install with \pythoninline{uv sync}, and run the tests with \pythoninline{uv run pytest}. Runs are started with \pythoninline{uv run run_sim} and \pythoninline{uv run run_real}, and an existing run can be re-plotted with \pythoninline{uv run plot_run <run directory>}.

The files handed out are:
\begin{itemize}
	\item \pythoninline{configs/}: the run configurations. Everything marked \pythoninline{# TODO tune} is yours to experiment with in Task \ref{q:task02} and \ref{q:task03}.
	\item \pythoninline{preprocessing.py}: the odometry and lidar front-end. \pythoninline{relative_pose} and \pythoninline{preintegrate} are yours; \pythoninline{detect_trees}, which converts a raw lidar scan into range-bearing measurements, is given. \textbf{NB:} you do not need to change anything below the line in this file.
	\item \pythoninline{factor_graph.py}: factor construction, the measurement model, covariance recovery and the innovation covariance. Most of your work is here.
	\item \pythoninline{landmark_manager.py}: landmark birth. The \(M\) of \(N\) rule is yours; the rest is given.
	\item \pythoninline{data_association.py}: the JCBB algorithm, and a ground-truth associator you can switch on for debugging on the simulated data set. \textbf{NB:} you do not need to do anything in this file.
	\item \pythoninline{slam.py}: the main loop that ties all of the above together. Reading it is the fastest way to understand what happens in one time step. \textbf{NB:} you do not need to do anything in this file.
	\item \pythoninline{loaders/}, \pythoninline{logger.py}, \pythoninline{plotter.py}, \pythoninline{plotting/}: data set adapters, run logging, and all the plotting. \textbf{NB:} you do not need to do anything in these files.
\end{itemize}

Two conventions in this code base are easy to get backwards, and both produce a system that runs and looks plausible while being wrong: measurements are ordered \([\text{range}, \text{bearing}]\) while GTSAM's \pythoninline{BearingRangeFactor2D} takes bearing first, and all pose covariances and Jacobians live in the tangent space of the current estimate rather than in raw \((x, y, \psi)\) coordinates. Both are discussed where they matter in Task \ref{q:task01}.
