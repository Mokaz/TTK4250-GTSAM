\titledquestion{Run factor graph SLAM on simulated data}
\label{q:task02}
The simulated dataset consists of
\begin{itemize}
    \item odometry (K, 3): the measured movement of the robot in its body frame,
    \item z (K,): a list of the detections at each time step, each of shape (number of measurements, 2),
    \item poseGT (K, 3): the true pose at each time step,
    \item landmarks (L, 2): the true landmark positions.
\end{itemize}

The initial tuning is in \pythoninline{configs/sim_default.yaml}. Everything marked \pythoninline{# TODO tune} is yours to change. It is a \emph{working baseline}: the run completes and the map is mostly right, but there is room for improvement in both accuracy and consistency. The pose NEES sits above its expected value, and the landmark NIS below it. With a correct Task~\ref{q:task01}, the baseline maps 72 of the 78 true landmarks, with 3 spurious ones, and gives a pose ANEES of 8.37. The run is deterministic, so if yours differs, check Task~\ref{q:task01} before you start tuning.

\paragraph{Running.} From the handout folder, run the baseline with
\begin{center}
    \pythoninline{run_sim --output-dir runs/sim/baseline}
\end{center}
For each tuning set, copy \pythoninline{configs/sim_default.yaml} to a new file, change its values, and run it with \pythoninline{--config} pointing at that file and its own \pythoninline{--output-dir}. A run takes about 10--15 seconds. The run directory keeps the figures, the config used and the summary (in \pythoninline{metadata.json}). \pythoninline{plot_run <run directory>} re-plots a finished run, and \pythoninline{--no-show-plots} skips the plot windows.

Find 3 sets of tuning values that differ from the baseline in different ways, and explain the results you get with them. For example:
\begin{itemize}
    \item a set that performs better than the baseline in some way,
    \item a set with similar errors but poor consistency,
    \item a set that maps noticeably fewer landmarks, and how that affects the trajectory.
\end{itemize}

Every run prints a summary of the averaged NEES and NIS (the landmark ANIS per degree of freedom, since the number of associated landmarks varies). To judge consistency, compare each average with its expected value, and check that about 95\% of the per-step values fall inside their bounds. Do not rely on the 95\% interval of the average alone: (4.67) assumes independent errors, but the errors of neighbouring poses in a smoother are strongly correlated, so even with the correct noise, one run's ANEES can land anywhere between about 1.5 and 8.

Every simulated run also prints a map-quality summary, which compares the map with the true landmarks. Each map landmark is paired with at most one true landmark, closest pairs first and only within 3\,m, and only the true landmarks the run actually observed are counted:
\begin{itemize}
    \item \emph{Mapped}: a true landmark with a map landmark paired to it. The RMS position error is taken over these pairs.
    \item \emph{Missed}: an observed true landmark with no map landmark paired to it. Either it was never confirmed, because it was not seen in \(M\) of \(N\) steps or its measurements kept being associated elsewhere, or its estimate drifted more than 3\,m away.
    \item \emph{Duplicate}: an extra map landmark within 3\,m of a true landmark that already has its pair. Data association failed to match a measurement to the landmark already in the map, and a new landmark was born from it instead.
    \item \emph{Spurious}: a map landmark with no true landmark within 3\,m. It was born from a wrong measurement or a wrong association, or its estimate has drifted far from where the landmark is.
\end{itemize}
Duplicates point at the front-end (association and landmark birth); missed and spurious landmarks can come from either end.

\textit{Note}: The runtime of JCBB grows quickly with the number of duplicate landmarks, because each one gives a measurement more candidates to pair with. A tuning that creates duplicates (noise values so small that the gates reject true re-observations, or landmark birth on a single sighting, \(M = N = 1\), with a wrong noise model) can slow a run from seconds to minutes. If a run slows down substantially, stop it with Ctrl+C. The run so far will be saved, and its map-quality summary shows whether duplicates are the cause.
