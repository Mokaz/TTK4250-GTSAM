\titledquestion{One bad association}
\label{q:task04}
In this short task, we will look at what happens when a data association is wrong, and how a robust loss function can help. The experiment is quick to run, and its discussion should be included in the report as one figure and a paragraph.

The config \pythoninline{configs/task4.yaml} sets \pythoninline{inject_wrong_at_step: 600} under \pythoninline{association}, which re-pairs one measurement with the wrong landmark at step 600. Everything else is the same as in \pythoninline{configs/sim_default.yaml}, the default tuning from Task~\ref{q:task02}. Run it with
\begin{center}
    \pythoninline{run_sim --config configs/task4.yaml --output-dir runs/sim/task4}
\end{center}
and compare it with your baseline run from Task~\ref{q:task02}: explain what this single wrong association does to the trajectory and the map, using the error values and landmark counts from the run summary. How does the NIS behave at step 600 and in the steps after it, and why?

The Huber loss is a robust loss function (GTSAM calls it a robust kernel, hence the config name) that is quadratic for small errors and linear for large ones:
\[
    \rho_\delta(e) =
    \begin{cases}
        e^2, & |e| \le \delta, \\
        2\delta|e| - \delta^2, & |e| > \delta.
    \end{cases}
\]
With \pythoninline{backend.robust_kernel: huber}, each landmark term in (9.6) changes from
\[
    \|h(x_k, m^i) - z^i_k\|_R^2
    \quad\text{to}\quad
    \rho_\delta\big(\|h(x_k, m^i) - z^i_k\|_R\big),
\]
where \(\|h(x_k, m^i) - z^i_k\|_R\) is the measurement error normalized by the measurement noise covariance \(R\) (its Mahalanobis distance), so the threshold \(\delta\), set by \pythoninline{backend.huber_k}, is in units of measurement noise standard deviations. For more background, see the \href{https://en.wikipedia.org/wiki/Huber_loss}{Wikipedia article on the Huber loss}\footnote{\href{https://en.wikipedia.org/wiki/Huber_loss}{https://en.wikipedia.org/wiki/Huber\_loss}}, which defines it with an extra factor \(\tfrac12\).

Edit \pythoninline{configs/task4.yaml}: set \pythoninline{backend.robust_kernel: huber}, and run the simulation again with
\begin{center}
    \pythoninline{run_sim --config configs/task4.yaml --output-dir runs/sim/task4_huber}
\end{center}
Explain how this changes the cost function (9.6) for the wrong measurement, and why that helps.

Finally, compare with EKF-SLAM (Sec.\ 7.2): what are your options for recovering from a wrong association in each of the two frameworks?
